# 资源分类规则

## 固件与内核

普通固件按明确机型分类。同名主干的 ROM、NOR、NAND 可组成候选包，但仍需核实组合、固件版本和授权。`-bak` 等备份变体保留独立身份，不与主包自动混用。文件名中的版本数字不自动作为经确认的版本号。

NC2000 / NC2600 第三方内核归入 `firmware/nc2000-nc2600-kernels`，不作为独立设备型号：

| 文件主干 | 内核名称 | 作者 |
| --- | --- | --- |
| `35` | 3.5内核 | Sun |
| `41` | 4.1内核 | qiqi |
| `41cam` | 4.1内核保留剑桥版 | qiqi |
| `epc50`、`ecp50` | 5.0内核 | epc |
| `fc42` | 非常4.2内核 | 41824984 |

`epc50` 与 `ecp50` 均作为可识别的命名形式保留，文件不会擅自改名。作者和内核名称属于分类信息，不等于已取得再分发授权；两种目标机型的实际运行兼容性仍需分别确认。

`.nand0` 为临时文件，不收录、不导出。`.state` 为会话状态，不作为固件收录。NOR/NAND 可能包含运行时修改和个人数据，发布前必须核实，不能根据文件名或大小认定为干净出厂镜像。

NC2000TW 不未经验证映射为 NC2000。应用尚未支持的机型可以作为明确分类保留候选，但不能被标注为当前应用可用。

## 程序

分类依据是目录结构和文件类型共同提供的线索，不仅依据扩展名或程序文件名：

- 目录中明确出现 NC1020、NC2600、NC3000、PC1000 等机型，归入相应机型；保留原目录以便追溯。
- GvBasic 目录中的 BAS 可归入 `basic/gvbasic`；没有机型信息时不臆测兼容机型。
- LAVA 目录中的 LAV 可归入 `lava/lava`；必须核实所需解释器，不当作原生 BIN 自动安装。
- GvBasic 下没有明确机型线索的 BIN 不能仅凭上级目录视为 BASIC 程序。
- 泛化的 BIN、6502 汇编等目录若没有明确机型或运行环境线索，暂不收录。

目录标注是分类依据，不是兼容性验证结果；NC2600 专用程序不能自动标为 NC2000 通用。BAS 可能是分词或二进制格式，不强制按文本转换。

## 排除项与配套文件

不自动收录压缩包、PC 工具、源码、电子书、音视频、图片、隐藏文件、符号链接、私人状态文件和需要特殊权利审核的工具；不执行其中的程序、宏或脚本。

主程序可能依赖 DAT、字体、解释器或其他配套资料，收录时应人工检查。依赖未确认的程序不能作为完整可用包发布。
